# nucleo-h563zi-adc-MCP3564R

This is an example of how to use an STM32 microcontroller to drive an MCP3564R analog-to-digital converter. Specifically, it works with the STM32H563-series microcontroller on the Nucleo H536ZI development board. My hope is that this might serve as a useful starting point for anyone who would like to drive this part (or a similar part from the same family) with an STM32H5 microcontroller (or a microcontroller from a related family).

## Overview

There are two main task loops: in MUX mode, we do individual one-shot conversions. In scan mode, we program a series of conversions and let the ADC run, and get an interrupt via a GPIO pin every time a conversion result is ready. To build the code for these different modes, set MCP3564_USE_MODE to MCP3564_USE_MUX_MODE or MCP3564_USE_SCAN_MODE in adc_MCP3564R_config.h.

You can configure single-ended or double-ended measurement by setting MCP3564_INPUTS_TYPE to MCP3564_INPUTS_SE or MCP3564_INPUTS_DE in adc_MCP3564R_config.h.

Finally, you can also build the code to drive the SPI transactions using the HAL interrupt APIs, or the DMA APIs. Set MCP3564_HAL_SPI_MODE to MCP3564_USE_HAL_SPI_INT_MODE or MCP3564_USE_HAL_SPI_DMA_MODE in adc_MCP3564R_config.h. Note that I don't provide an option to use blocking calls, since I try to avoid blocking in my applications as much as possible.

Peripheral initialization code was generated using STM32CubeMX (currently, version 6.18.1), and the included project is for use with the STM32CubeIDE (currently, version 2.2.0). It uses FreeRTOS. The FreeRTOS files are also generated by STM32CubeMX, which must have the appropriate FreeRTOS middleware package installed. Hopefully you might find this a useful demonstration of various FreeRTOS APIs, especially direct-to-task notifications.

## The UART Debugging Menu

I have included a simple debugging menu I use in more complex projects. It uses the microcontroller's UART5. On the H536ZI board you can connect pin PC12 (CN11 connector pin 3, UART5_TX) to a USB-to-UART adapter RX pin, and pin PD2 (CN11 connector pin 4, UART5_RX) to the adapter TX pin. This will work with an Adafruit FT232H breakout board, an Adafruit CP2102N breakout board, or similar breakout board or cable. I use PuTTY as a serial terminal. The project configures UART5 to run at 115200 bits per second, 8 bits, no parity.

## Connecting the Nucleo H536ZI to an MCP3564R ADC

This part is up to you. I have built several hand-soldered prototype boards that plug into the Nucleo board, but I don't have a PCB design I can provide.

The project configures the ADC to use its internal voltage reference. If you supply an external voltage reference, change MCP3564_USE_EXT_VREF in adc_MCP3564R_config.h to 1, and make sure to put the correct nominal voltage value in adc_MCP3564R_external_vref.h.

The project takes advantage of the ADC's interrupt pin to determine when conversion data is available. Pin PA2 is configured as an GPIO input generating an EXTI2 interrupt when the ADC pulls it low. No pull-up is required. If you don't want to use this interrupt to signal when data is avaialble, you can set MCP3564_USE_CONV_COMPLETE_INT to 0 in adc_MCP3564R_config.h. If you do this, you'l have to add code to poll the ADC and verify data is avaialble before reading it, since the code I've supplied here doesn't handle this use case.

The project configures pin PD14 (timer 4 channel 3) to generate a 20MHz conversion clock for the ADC, which is the maximum supported clock rate. If this clock is too fast for your prototype hardware, set the prescaler for TIM4 CH3 to a value greater than 1. Setting it to 7 should result in dividing the upstream 160MHz clock by 8 instead of 2, resulting in a clock output of 5MHz.

If you don't want to use this pin as an external clock, you can set MCP3564_USE_EXT_CLOCK to 0 in adc_MCP3564R_config.h and the ADC will be configured to use a less accurate internal clock. According to the datasheet this will result in the ADC using a clock frequency somewhere around 5MHz, but note that the datasheet says "the precision of the center frequency is approximately +/-30% from chip to chip."

If you want to experiment with the project without an actual ADC, note that the code that writes and reads back register values in adc_configure() will fail. But you could still wire up a logic analyzer and step through the code to observe the outgoing SPI traffic (I use a Digilent Analog Discovery Pro 2230).
